# Отзывы организаций с Яндекс.Карт (тестовое)

Вставляешь ссылку на организацию с Яндекс.Карт → логинишься → видишь её рейтинг,
счётчики и отзывы с постраничным листанием.

Стек: **Laravel 12** (API) + **Vue 3** (SPA). Парсинг сделан прямо на PHP.

> ⚠️ Честно: это **MVP**, сделал не всё, что в ТЗ. Что работает и что не успел —
> расписал ниже, там же — как планировал доделать остальное. Основной сценарий
> (логин → ссылка → отзывы) рабочий.

---

## Что работает

- **Вход** по логину/паролю (Sanctum, cookie-сессия). Регистрации нет, есть один
  сид-пользователь: `demo@example.com` / `password`.
- **Добавление организации** по ссылке с валидацией (проверяем, что это реально
  ссылка на карточку Яндекс.Карт, вытаскиваем id/slug, режем query-мусор).
- **Сбор данных** сразу при добавлении: рейтинг, **число оценок** и отдельно
  **число отзывов** (это разные величины — не путаю) и **первые ~50 отзывов**.
- **Страница организации**: сводка + отзывы по **50 на страницу**, листаются без
  перезагрузки. Отзывы отдаются из своей БД, так что листание мгновенное и Яндекс
  на каждый клик не дёргается.
- **Повторный сбор** (кнопка «Обновить») не плодит дубли — upsert по id отзыва.
- **Тесты**: парсер (разбор состояния страницы) + авторизация — `php artisan test`
  (14 штук, зелёные).

## Как достаю отзывы (без капчи)

Страница `/reviews/` у Яндекса рендерится сервером, и всё состояние лежит прямо в
HTML — в `<script class="state-view">` обычным JSON. Там уже есть рейтинг, оба
счётчика и первые ~50 отзывов, причём отдаётся это по простому GET **без капчи**.
Достаю этот JSON и рекурсивно нахожу узел организации (`ratingData`) и блок
отзывов (`reviewResults.reviews`) — код в
[`YandexParser`](backend/app/Services/Yandex/YandexParser.php).

## Что НЕ успел (и как бы доделал)

**1. Полный сбор отзывов (больше первых ~50).**
Дальше первой страницы Яндекс подгружает отзывы отдельным XHR `fetchReviews`, а он
**подписан**: параметр `s=` считается прямо в браузере плюс ротация
`csrfToken`/`sessionId`. Повторять подпись на бэке — хрупко (ломается от каждого
обновления антибота). Правильный путь — **headless-браузер**: открыть страницу в
Playwright, дать ей самой слать подписанные запросы, а нам через
`page.on('response')` собирать ответы и прокруткой докручивать остальное. Набросок
такого сборщика уже лежит в [`scraper/`](scraper/src/yandexScraper.js) (Node +
Playwright), но **к бэку я его не подключил** — на PHP-стороне пока только первая
страница. Доделать = поднять этот сервис и ходить в него из `YandexParser` вместо
прямого GET.

**2. Нормальная обработка смены вёрстки / антибота.**
Сейчас если разметка изменилась или прилетела капча — кидаю одну общую ошибку и
показываю её текст на фронте (`parse_error`). Этого мало. Как доделал бы:
- отдельно различать капчу, изменившуюся вёрстку и сетевую ошибку (по HTTP-коду,
  по признакам капчи в HTML, по наличию ключевых узлов в state);
- сделать «самопроверку» ответа: есть организация, рейтинг в диапазоне 0–5,
  счётчик > 0 ⇒ отзывы не пустые — иначе не сохранять мусор, а падать явно;
- слать алерт (лог/уведомление), чтобы поломку было видно сразу.
Метку `// TODO` оставил прямо в коде парсера и контроллера.

**3. Очередь под много организаций (сеть из ~50 филиалов).**
Сейчас парсю **синхронно** в HTTP-запросе — для одной организации и одной страницы
это быстро и норм. Для сети так нельзя: долго и хрупко. Доделал бы через **очередь**
— по job на организацию (`ParseOrganizationReviews`), с ретраями и нарастающим
backoff, а фронт опрашивал бы статус. В первой версии проекта такая джоба была, но
под MVP я её убрал ради простоты — вернуть недолго.

**4. Docker / деплой.**
`docker-compose.yml` в репо остался от полной задумки (php-fpm, nginx, MySQL,
scraper) и под текущую лин-версию не допилен. Локально всё гоняется без Docker на
SQLite (см. ниже). Живого хостинга пока нет.

**5. Тесты.**
Покрыл только ядро (парсер) и авторизацию. Не хватает интеграционного теста на
`POST /organizations` с замоканным `Http::fake()` и e2e на фронте.

## Запуск локально

Нужны PHP 8.2+ и Node 18+. БД — SQLite, поднимать ничего не надо.

**Бэкенд:**

```bash
cd backend
composer install
cp .env.example .env      # если .env ещё нет
php artisan key:generate
php artisan migrate:fresh --seed
php artisan serve
```

> На моей машине в php.ini висел Xdebug и подвешивал CLI — если `artisan` долго
> «думает», запускай с `XDEBUG_MODE=off php artisan …`.

**Фронтенд:**

```bash
cd frontend
npm install
npm run dev
```

Открываешь фронт, логинишься `demo@example.com` / `password`, на странице настроек
вставляешь ссылку вида `https://yandex.ru/maps/org/<slug>/<id>/reviews/`.

## Структура

- `backend/` — Laravel API. Парсер — `app/Services/Yandex/` (`YandexUrl` — разбор
  ссылки, `YandexParser` — разбор страницы). Контроллеры тонкие.
- `frontend/` — Vue 3 (Composition API) + Pinia + vue-router + axios.
- `scraper/` — **WIP** headless-сборщик на Playwright (см. пункт 1 выше), пока не
  подключён.
